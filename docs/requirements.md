# Контекст
Есть необходимость в продукте, который бы обеспечил качественную обработку многоканальный запросов в техническую поддержку, согласно SLA. Необходим контроль со стороны администрации и модерации за процессами и KPI операторов.

## Бизнес-требования
- БТ-1. Снижение запросов с просроченным SLA  с 10% до 3% за 1 квартал 2027г. 
- БТ-2 Снижение ошибочных консультаций с 5 % до 2% за  1 квартал 2027 г
- БТ-3 Снижение простоя операторов между обработкой обращений с 10 до 3 минут.

## Пользователи и их задачи
Роли: оператор, начальник смены, пользователь  и модератор.
- Оператор: рассматривает обращения, осуществляет консультации пользователей в процессе созвона либо письменно в чате. 
- Начальник смены: Контролирует присутствие операторов на местах, отслеживает количество просроченных обращений и простои в работе операторов.
- Пользователь: пишет в поддержку с проблемами по продукту
- Модератор: оценивает ответы операторов по чек листу, информирует о результатах начальника, выставляет средний балл для KPI операторам.

## Пользовательские требования
- ПТ-1. Пользователь хочет чтобы обращения не терялись и рассматривались оперативно → связано с БТ-1, БТ-3.
- ПТ-2. Операторы хотят возможность видеть, принимать и обрабатывать обращения со всех каналов в одном удобном интерфейсе связано с БТ-1, БТ-2 и БТ-3
- ПТ-3. Начальник смены хочет видеть в режиме реального времени карту выходов сотрудников а также их показатели SLA и простоя → связано с БТ-1, БТ-2 и БТ-3.
- ПТ-4 Модератор должен видеть ответ оператора на каждое обращение в  своей карточке → связано с БТ-2.

## Функциональные требования
- ФТ-1. Система ежедневно формирует отчет ежедневно по тем карточкам, где нарушено SLA под отчет попадаю все операторы→ связано с ПТ-3 
- ФТ-2. Система формирует обращения из всех источнков, обрабатывает и отображает оператору → связано с ПТ-2
