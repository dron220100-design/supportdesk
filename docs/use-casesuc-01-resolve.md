# UC-01. Оператор отмечает обращение решённым
 
**Актёр:** Оператор

**Цель:** Привести обращение в статусе «Решено»

**Предусловия:** 

1. Оператор авторизован в системе
2. Обращение находится в статусе «в работе»

## Основной поток

1. Оператор выбирает активное обращение
2. Система открывает карточку обращения
3. Оператор переводит обращения в статус «решено»
4. Система проверяет текущий статус обращения
5. Система изменяет статус обращения на «решено»
6. Система сохраняет данные об изменении статуса
7. Система уведомляет клиента об изменении статуса обращения
8. Система отображает оператору сообщение об успешном изменении статуса

## Альтернативы
A1 (к шагу 4). Обращение уже имеет статус «решено» или «закрыто»
- 1. Система отменяет операцию изменения статуса
- 2. Система отображает оператору сообщение о невозможности выполнения действия
- 3. Оператор возвращается к карточке обращения

A2 (к шагу 7). Отправка уведомлений недоступна
   - 1. Система фиксирует невозможность доставки уведомления клиенту
   - 2. Система добавляет запись об этом в лог уведомлений
   - 3. Система продолжает выполнение основного потока с шага 8

## Исключения
И1 (к шагу 4). Потеря соединения с сервером при проверке статуса
   - 1. Система отображает оператору сообщение об ошибке соединения
   - 2. Статус обращения остается прежним

И2 (к шагу 6). Ошибка записи в базу данных при сохранении изменений
   - 1. Система откатывает транзакцию
   - 2. Система отображает оператору сообщение о сбое сохранения
   - 3. Статус обращения остается прежним

И3 (к шагу 7). Ошибка почтового сервера при отправке уведомления клиенту
   - 1. Система фиксирует сбой отправки в системном журнале
   - 2. Система прерывает отправку уведомления
   - 3. Основной поток продолжается с шага 8

## Постусловия
1. Обращение переведено в статус «решено»
2. В истории обращений зафиксировано событие смены статуса
3. Клиент уведомлен об изменении статуса
